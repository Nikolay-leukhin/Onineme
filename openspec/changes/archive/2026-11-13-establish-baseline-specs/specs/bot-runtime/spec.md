# Spec Delta

## Purpose

Техническое поведение процесса бота: совместная работа диалогов с пользователями и фоновых циклов, источники конфигурации, ожидания к окружению и поведение при перезапуске.

## ADDED Requirements

### Requirement: Совместная работа диалогов и фоновых циклов
Один процесс бота SHALL одновременно обслуживать сообщения пользователей, синхронизацию каталога (title-catalog) и проверку обновлений (episode-notifications). Фоновый цикл MUST NOT ждать завершения другого.

#### Scenario: Команда во время синхронизации каталога
- **WHEN** идёт многоминутная синхронизация каталога и пользователь отправляет /help
- **THEN** бот отвечает справкой, не дожидаясь конца синхронизации

#### Scenario: Проверка обновлений во время синхронизации
- **WHEN** идёт синхронизация каталога и наступает время проверки обновлений
- **THEN** проверка обновлений выполняется по своему расписанию

### Requirement: Отбрасывание накопившихся входящих
При запуске бот SHALL отбрасывать сообщения и нажатия, отправленные пользователями, пока бот не работал. Они MUST NOT обрабатываться после запуска.

#### Scenario: Команда во время простоя
- **WHEN** пользователь отправил /start, пока бот был остановлен, и затем бот запустился
- **THEN** бот не отвечает на этот /start

### Requirement: Диалоговое состояние не переживает перезапуск
Незавершённые диалоговые сценарии (карусель, поиск, список подписок) SHALL храниться только в памяти процесса и SHALL NOT восстанавливаться после перезапуска.

#### Scenario: Поиск через перезапуск
- **WHEN** бот ожидал поисковый запрос, перезапустился, и пользователь отправил текст
- **THEN** текст не обрабатывается как поисковый запрос

### Requirement: Конфигурация из окружения
Бот SHALL читать токен Telegram, параметры подключения к PostgreSQL (хост, порт, пользователь, пароль, имя БД) и MongoDB (URL, имя БД) из переменных окружения. Также SHALL поддерживаться файл .env.

#### Scenario: Запуск с .env
- **WHEN** параметры заданы в файле .env в корне проекта
- **THEN** бот использует их при запуске

### Requirement: Схема БД существует заранее
Бот SHALL NOT создавать таблицы PostgreSQL при запуске. Схема пользователей, тайтлов и подписок MUST существовать до запуска бота.

#### Scenario: Запуск на пустой БД
- **WHEN** бот запускается на PostgreSQL без таблиц
- **THEN** бот не создаёт таблицы
