# Spec Delta

## Purpose

Запуск бота вместе с его хранилищами (PostgreSQL и MongoDB) в контейнерах одной командой: порядок старта, сохранность данных между перезапусками и автоматическое восстановление после падений.

## ADDED Requirements

### Requirement: Запуск всех сервисов одной командой
Репозиторий SHALL содержать описание контейнерного окружения, по которому одна команда `docker compose up` собирает образ бота и запускает три сервиса: бот, PostgreSQL и MongoDB. Дополнительная ручная подготовка, кроме файла `.env` с токеном, MUST NOT требоваться.

#### Scenario: Первый запуск на чистой машине
- **WHEN** на машине с Docker в корне репозитория есть `.env` с `TELEGRAM_TOKEN` и выполняется `docker compose up -d --build`
- **THEN** все три сервиса запущены, и `docker compose ps` показывает их в состоянии running (хранилища — healthy)

#### Scenario: Бот отвечает после запуска
- **WHEN** сервисы запущены и пользователь отправляет боту /start
- **THEN** бот отвечает приветствием

### Requirement: Бот стартует после готовности хранилищ
Сервис бота SHALL запускаться только после того, как PostgreSQL и MongoDB прошли проверку готовности.

#### Scenario: Медленный старт PostgreSQL
- **WHEN** PostgreSQL ещё инициализирует данные при первом запуске
- **THEN** бот не запускается до готовности PostgreSQL и не падает с ошибкой подключения

### Requirement: Сохранность данных между перезапусками
Данные PostgreSQL и MongoDB SHALL храниться в именованных томах и MUST сохраняться при пересоздании контейнеров (`docker compose down` без `-v` и последующий `up`).

#### Scenario: Пересоздание контейнеров
- **WHEN** пользователь подписался на тайтл, затем выполнены `docker compose down` и `docker compose up -d`
- **THEN** подписка пользователя сохранилась

### Requirement: Автоматический перезапуск
Все сервисы SHALL автоматически перезапускаться после аварийного завершения, пока их не остановили явно.

#### Scenario: Падение процесса бота
- **WHEN** процесс бота завершился с ошибкой
- **THEN** контейнер бота запускается заново без участия человека

### Requirement: Секреты не попадают в образ и репозиторий
Токен Telegram и пароли SHALL передаваться в контейнеры через окружение во время запуска. Файл `.env` MUST NOT копироваться в образ и MUST NOT отслеживаться git. В репозитории SHALL быть пример `.env.example` без реальных значений.

#### Scenario: Сборка образа
- **WHEN** образ бота собран из репозитория, где есть `.env`
- **THEN** файла `.env` внутри образа нет

#### Scenario: Подготовка окружения
- **WHEN** новый разработчик клонирует репозиторий
- **THEN** он находит `.env.example` с перечнем нужных переменных и копирует его в `.env`
